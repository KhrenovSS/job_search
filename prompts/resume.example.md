# Резюме владельца (образец; реальный файл — prompts/resume.md, он в .gitignore)

`prompts/resume.md` — текст резюме, единственный источник фактов для писем: подставляется как `{resume}` в
`cover_letter.md` (отклик на вакансию), `company_offer.md` (предложение компании), `profi_bid.md` (заказ profi.ru)
и в чеклист редактора `letter_review.md`. Основа создаётся из PDF-экспорта hh.ru:

    pdftotext -layout Резюме.pdf - | sed '/Резюме обновлено/d' > prompts/resume.md

Дальше файл правится руками, потому что письмам нужно то, чего в экспорте нет:

- **Контакты для подписи** — имя, телефон и e-mail в том виде, в каком они должны стоять в письме: подпись из
  четырёх строк (имя, «работаю по договору (ИП)», телефон, e-mail) проверяется кодом (`llm/letter_checks.py`,
  `PHONE_RE` / `EMAIL_RE`), без телефона и почты в резюме письмо не пройдёт проверку.
- **Раздел «Ключевые проекты»** по отраслям, каждый проект — «объект → что сделано и на чём → результат».
  Из него письмо берёт аналогичный опыт как сделанное («ПО для КНС и насосных писал на ОВЕН/Schneider —
  беру программную часть на подряд»), а таблица «отрасль компании → проект из резюме» в `cover_letter.md`
  ссылается на эти же проекты. Незавершённый проект пометьте как пилот — письмо назовёт его текущей работой.
- **«Чем могу быть полезен» и «Как работаю»** — платформы, форматы, договор, передача исходников, поддержка
  после запуска. Без сумм: письмо денег не называет никогда.

Файл читается целиком при каждой генерации письма и входит в отпечаток правил (`cover_letters.rules_hash`): после
правки письма из очереди переписываются. Разделитель `---` в нём использовать нельзя.
